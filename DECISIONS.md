# Decisions

- **Gemini models:** gemini-2.5-flash for answers and gemini-embedding-001 for embeddings. Stable releases; model names are env variables so they can be swapped.
- **In-process ingestion queue:** no Redis or worker service, to keep deployment simple. Stuck jobs are marked failed on restart.
- **Health check:** uses the Mongoose connection state, not a database ping. The handler stays inline in the routes file as the one exception to the controller rule.
- **trust proxy = 1:** Render sits behind one proxy, so this lets rate limiting see the real client IP.
- **Error mapping:** a malformed ObjectId returns 400; an oversized JSON body returns 413.
- **Signup transaction:** tenant and admin IDs are created up front so both inserts can reference each other, and a failed user insert rolls back the tenant.
- **Stateless JWT:** requireAuth trusts a valid token without a database read. Deleting a user or changing a role takes effect when the token expires (1 day).
- **Password limits:** 8 to 72 characters and at most 72 UTF-8 bytes, because bcrypt ignores anything past 72 bytes. Login only checks that a password is non-empty.
- **JWT_EXPIRES_IN:** validated at startup. Digit-only values become numbers because jsonwebtoken treats numeric strings as milliseconds.
- **Port 5004:** port 5000 is used by AirPlay Receiver on macOS.
- **Chunk embeddings are checked on save:** Chunk rejects embeddings that aren't exactly EMBEDDING_DIMENSIONS finite numbers, because Atlas vector search silently skips wrong-sized vectors.
- **Optional arrays are omitted, not stored empty:** Message.sources and Chunk.embedding use default: undefined, so a missing embedding fails validation instead of saving as [].
- **One conversation index:** { tenantId, lastMessageAt, unansweredCount } serves both the full list and the "unanswered only" list, sorted by latest message.
- **MongoDB DNS:** some Indian ISPs fail the SRV lookup used by mongodb+srv:// connection strings (querySrv ENOTFOUND). Fixed by setting the Mac's DNS to 8.8.8.8 and 1.1.1.1.
- **Embeddings bypass LangChain:** @langchain/google-genai replaces a failed embedding batch with empty vectors instead of throwing, hiding 429s from retries. provider.js calls @google/genai directly for embeddings and uses LangChain only for chat.
- **768-dimension vectors are L2-normalized:** Gemini returns vectors with a norm of about 0.59 below 3072 dimensions. Normalizing keeps cosine scores consistent.
- **Similarity threshold starts at 0.85, not 0.75:** Gemini scores unrelated text around 0.90 on Atlas's scale, so 0.75 would let every chunk through. To be tuned on real query-to-chunk scores.
- **Patient retries for embeddings only:** ingestion runs in the background and honors Gemini's suggested retry delay; chat keeps quick retries because a visitor is waiting.
- **The vector index script never drops anything:** a mismatched definition stops the script, because dropping the index would break search until every document is re-embedded.
- **Stagehand peer overrides:** @langchain/community lists @browserbasehq/stagehand as an optional peer that wants dotenv 16 and zod 3. package.json overrides point those two peers at our own dotenv and zod so installs work without --legacy-peer-deps. Stagehand is never imported.
- **PDFs are passed to PDFLoader as a Blob:** the loader reads the Buffer's underlying ArrayBuffer, which for small multer uploads can be a shared memory pool holding other bytes. A Blob gives it a private copy.
- **pageCount is the PDF's total page count,** including pages with no text, so it matches what the admin sees in the file.
- **Upload type check:** the extension and the MIME type must both match, and must match each other (.pdf with application/pdf, .txt with text/plain). Content is not sniffed; a fake PDF fails ingestion with "Could not read this PDF".
- **Document cap counts every document,** including failed ones. Admins delete failed documents to free a slot. Two simultaneous uploads at the limit can both pass the check; the cap is soft.
- **Delete-during-ingestion:** the pipeline checks the document is still processing before it starts, before inserting chunks, and in the same update that marks it ready. If the ready update matches nothing, it deletes the chunks it just inserted. The API deletes the document first, then its chunks.
- **Stuck-job recovery uses the spec's 10-minute rule:** it protects jobs an old instance may still be finishing during a deploy. A document uploaded less than 10 minutes before a crash stays "processing" until the next restart; the admin can delete and re-upload it.
- **Ingestion error messages are fixed strings:** "No extractable text", "Could not read this PDF", an embedding failure message, or a generic one. The real error is logged on the server, never stored on the document.
