# Decisions

- **Gemini models:** gemini-3.5-flash-lite for answers and gemini-embedding-001 for embeddings. Model names are env variables so they can be swapped. The chat model was first gemini-2.5-flash; see the quota and model switch entries below.
- **In-process ingestion queue:** no Redis or worker service, to keep deployment simple. Stuck jobs are marked failed on restart.
- **Health check:** uses the Mongoose connection state, not a database ping. The handler stays inline in the routes file as the one exception to the controller rule.
- **trust proxy = 1:** Render sits behind one proxy, so this lets rate limiting see the real client IP.
- **Error mapping:** a malformed ObjectId returns 400; an oversized JSON body returns 413.
- **Signup transaction:** tenant and admin IDs are created up front so both inserts can reference each other, and a failed user insert rolls back the tenant.
- **Stateless JWT:** requireAuth trusts a valid token without a database read. Deleting a user or changing a role takes effect when the token expires (1 day).
- **Password limits:** 8 to 72 characters and at most 72 UTF-8 bytes, because bcrypt ignores anything past 72 bytes. Login only checks that a password is non-empty.
- **JWT_EXPIRES_IN:** validated at startup. Digit-only values become numbers because jsonwebtoken treats numeric strings as milliseconds.
- **Port 5004:** port 5000 is used by AirPlay Receiver on macOS.
- **Chunk embeddings are checked on save:** Chunk rejects embeddings that aren't exactly EMBEDDING_DIMENSIONS finite numbers, because Atlas vector search silently skips wrong-sized vectors.
- **Optional arrays are omitted, not stored empty:** Message.sources and Chunk.embedding use default: undefined, so a missing embedding fails validation instead of saving as [].
- **One conversation index:** { tenantId, lastMessageAt, unansweredCount } serves both the full list and the "unanswered only" list, sorted by latest message.
- **MongoDB DNS:** some Indian ISPs fail the SRV lookup used by mongodb+srv:// connection strings (querySrv ENOTFOUND). Fixed by setting the Mac's DNS to 8.8.8.8 and 1.1.1.1.
- **Embeddings bypass LangChain:** @langchain/google-genai replaces a failed embedding batch with empty vectors instead of throwing, hiding 429s from retries. provider.js calls @google/genai directly for embeddings and uses LangChain only for chat.
- **768-dimension vectors are L2-normalized:** Gemini returns vectors with a norm of about 0.59 below 3072 dimensions. Normalizing keeps cosine scores consistent.
- **Similarity threshold started at 0.85, not 0.75:** Gemini scores unrelated documents around 0.90 on Atlas's scale when comparing document to document, so the first guess was high. Calibration on real query-to-chunk scores replaced it with 0.81 (see below).
- **Patient retries for embeddings only:** ingestion runs in the background and honors Gemini's suggested retry delay; chat keeps quick retries because a visitor is waiting.
- **The vector index script never drops anything:** a mismatched definition stops the script, because dropping the index would break search until every document is re-embedded.
- **Stagehand peer overrides:** @langchain/community lists @browserbasehq/stagehand as an optional peer that wants dotenv 16 and zod 3. package.json overrides point those two peers at our own dotenv and zod so installs work without --legacy-peer-deps. Stagehand is never imported.
- **PDFs are passed to PDFLoader as a Blob:** the loader reads the Buffer's underlying ArrayBuffer, which for small multer uploads can be a shared memory pool holding other bytes. A Blob gives it a private copy.
- **pageCount is the PDF's total page count,** including pages with no text, so it matches what the admin sees in the file.
- **Upload type check:** the extension and the MIME type must both match, and must match each other (.pdf with application/pdf, .txt with text/plain). Content is not sniffed; a fake PDF fails ingestion with "Could not read this PDF".
- **Document cap counts every document,** including failed ones. Admins delete failed documents to free a slot. Two simultaneous uploads at the limit can both pass the check; the cap is soft.
- **Delete-during-ingestion:** the pipeline checks the document is still processing before it starts, before inserting chunks, and in the same update that marks it ready. If the ready update matches nothing, it deletes the chunks it just inserted. The API deletes the document first, then its chunks.
- **Stuck-job recovery uses the spec's 10-minute rule:** it protects jobs an old instance may still be finishing during a deploy. A document uploaded less than 10 minutes before a crash stays "processing" until the next restart; the admin can delete and re-upload it.
- **Ingestion error messages are fixed strings:** "No extractable text", "Could not read this PDF", an embedding failure message, or a generic one. The real error is logged on the server, never stored on the document.
- **Chat turn runs as a service generator:** rag.service's streamChatReply yields SSE events and the controller writes them, so services never touch res. The first event (meta) is pulled before SSE headers are sent, so a missing tenant or someone else's conversation still gets a normal JSON 404.
- **Assistant message is saved before sources and done:** a visitor who clicks thumbs up right after the answer finishes never gets a 404.
- **Conversation counters update per message:** messageCount, unansweredCount and lastMessageAt change atomically as each user and assistant message is saved, so a failed or abandoned answer leaves the counts correct.
- **History excludes the current message:** the last RAG_HISTORY_MESSAGES messages before the one being answered, so the first message has empty history and skips the rewrite call.
- **Client disconnect aborts the LLM calls:** the rewrite and answer calls get an AbortSignal tied to the response closing. No assistant message is saved, and the user message stays in the transcript without a reply.
- **"I don't know" answers send empty sources:** when the model answers "I don't know", the sources event is an empty array like the fallback, but the stored message keeps the retrieved chunks and scores for threshold tuning.
- **Whitespace before the first visible token is not streamed,** so an empty model answer can switch to FALLBACK_TEXT without the visitor seeing stray whitespace first.
- **Prompt delimiters are stripped case-insensitively,** including spaced variants like "</ context >", and history tags are stripped as well as context tags.
- **Feedback can be changed:** a second rating overwrites the first. Feedback on a user message, a message in someone else's conversation, or another tenant's message returns 404 MESSAGE_NOT_FOUND.
- **Feedback uses only the global rate limiter:** chatLimiter (20/min per IP and slug) covers the stream route only, so thumbs clicks don't use up a visitor's question budget.
- **tenant.service.js resolves slugs:** resolveTenant middleware calls a service instead of querying the Tenant model itself. This file is not in SPEC.md's folder list. The public tenants route can reuse it.
- **visitorId must be a UUID v4,** lowercased before comparison.
- **Public tenant config reuses the slug lookup:** GET /public/tenants/:slug calls tenant.service's getTenantBySlug and returns only name, botName and welcomeMessage. It validates the slug with the same schema as the chat routes.
- **Threshold calibration (Pinecrest Outfitters, 2026-11-21):** 10 answerable questions scored 0.8170 to 0.8597 at the top chunk; 5 in-domain unanswerable ones scored 0.7983 to 0.8149. 0.816 passes all 10 and blocks all 5, but the gap is only 0.002, so recheck it with more questions and other tenants before trusting it. The answer model's "I don't know" rule is the second safety net.
- **Threshold set to 0.81, below the calibrated 0.816:** blocking a question the documents can answer is worse than letting a borderline one through, because the answer prompt's "I don't know" rule catches those. 0.81 keeps a 0.007 margin under the lowest answerable score. It lets "What is your customer service phone number?" (0.8149) through; gemini-3.5-flash-lite correctly answered "I don't know" and the message was saved with answered=false.
- **Gemini free tier limits chat capacity:** on the free tier this key allowed 5 gemini-2.5-flash requests per minute and 20 per day, and the daily quota ran out during testing. A follow-up message uses two requests (rewrite and answer), so about 10 follow-ups a day across all tenants. Free-tier limits are per model, which is one reason for the model switch below. A production deployment needs a paid key whatever model is used.
- **Chat model switched to gemini-3.5-flash-lite:** gemini-2.5-flash's free daily quota was used up, and gemini-2.5-flash-lite returns 404 "no longer available to new users" for this key even though it is still listed. gemini-3.5-flash-lite is the replacement Google's error names. It works with the existing @langchain/google-genai setup without code changes. On Pinecrest it answered with citations, said "I don't know" for uncovered questions, rewrote follow-ups correctly, and ignored a prompt-injection request attached to a real question.
- **No thinking settings applied:** on gemini-3.5-flash-lite, the default, thinkingLevel LOW and thinkingLevel MINIMAL gave the same latency (medians 1.4 to 1.6 s for both rewrite and answer time-to-first-token, 3 runs each) and reported 0 thinking tokens in every run. provider.js is unchanged. Recheck if the chat model changes.
- **Conversation list filter and shape:** `unansweredOnly=true` returns conversations with unansweredCount > 0. Each item has exactly id, visitorId, title, messageCount, unansweredCount, lastMessageAt, createdAt and updatedAt. The query value must be the string "true" or "false"; anything else is a 400, because a plain boolean coercion would read "false" as true.
- **Conversation list sorts by lastMessageAt only:** adding _id as a tiebreaker would stop the { tenantId, lastMessageAt, unansweredCount } index from serving the sort. Two conversations with the same millisecond timestamp may swap order between pages.
- **Transcript fields:** the conversation uses the list item shape. Every message has id, role, content and createdAt. Assistant messages also have query, rewrittenQuery, sources (n, documentId, documentName, page, score), answered, feedback, feedbackAt and latencyMs, with null for missing values. Scores are shown because this is the tenant's own admin view and helps threshold tuning.
- **Transcript order is createdAt then _id:** the _id tiebreaker costs an in-memory sort, which is cheap for one conversation's messages and keeps a user message ahead of its reply if both share a timestamp.
- **Unanswered list filters on role "assistant" and answered false:** it uses the { tenantId, answered, createdAt } index, newest first. Missing query or rewrittenQuery values come back as null.
- **Staff can read conversations:** the conversation routes allow both admin and user roles. Documents and staff creation stay admin-only.
